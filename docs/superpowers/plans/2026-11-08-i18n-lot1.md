# Site bilingue — lot 1 (accueil, lobby, table) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Afficher en anglais, au choix, l'accueil, le lobby, l'attente en ligne et le cadre de la table, sans rien changer en français.

**Architecture:** Un module `web/src/i18n/` sans dépendance : un dictionnaire français de référence (`fr.ts`), un dictionnaire anglais typé sur lui (`en.ts`), un petit store (langue courante, `localStorage`, abonnement React). Les textes que l'hôte envoie à un invité deviennent des codes que l'invité traduit ; les noms des IA et des places libres se forment chez celui qui affiche.

**Tech Stack:** React 19, TypeScript, Vitest 3 (rendu `react-dom/server`), PeerJS.

**Spec:** `docs/superpowers/specs/2026-11-08-i18n-design.md`

## Global Constraints

- Deux langues seulement : `"fr" | "en"`. Le français est la référence ; `en` a le type `Dict = typeof fr`, donc une clé anglaise manquante casse `pnpm type-check`.
- Langue par défaut : `fr` si `navigator.language` commence par `fr`, `en` sinon ; choix retenu dans `localStorage` sous la clé `ludo-lang` (convention de `session/storage.ts` : `ludo-name`, `ludo-host`), lecture/écriture dans un try/catch.
- La langue ne passe jamais par le réseau ; le sélecteur n'existe que sur l'accueil.
- Noms anglais des jeux (les seuls qui diffèrent) : `cards-president` *President*, `pairs-continuous` *Continuous Pairs*, `pairs-auberge` *Regent*, `tigre-euphrate` *Tigris & Euphrates*, `cryptide` *Cryptid*, `riichi` *Riichi Mahjong*. En français : le `name` du moteur, inchangé.
- Les messages `Illegal` du moteur, les plateaux et les rappels de règles des jeux restent hors lot (français).
- Protocole : ne jamais envoyer `undefined` (PeerJS le change en `null`) ; `PROTOCOL_VERSION` passe de 3 à 4.
- En FR, l'affichage reste identique à aujourd'hui : les tests existants passent sans changer leurs textes attendus (sauf les refus, qui deviennent des codes).
- Commits avec l'e-mail du dépôt (`marc.camuzat@gmail.com`, déjà configuré), messages en français comme l'historique.

## Review Focus

1. Une langue enregistrée invalide (`"de"`, chaîne vide) ou un `localStorage` qui lève : on retombe sur la langue du navigateur, sans planter. → test dans la tâche 1.
2. Un invité anglais face à un hôte français : refus (table complète, versions différentes) et nom des IA dans sa langue. → tests dans les tâches 4 et 5.
3. Un refus du moteur relayé par l'hôte garde son texte exact (il reste en français). → test dans la tâche 5.
4. Le tri des jeux suit la langue affichée (*Continuous Pairs* avant *Deadfall* en anglais, *Jour de chance* après *Deadfall* en français). → test dans la tâche 2.
5. Les tests d'un fichier qui passe en anglais remettent le français ensuite, pour ne pas contaminer les autres. → `afterEach(() => setLang("fr"))` dans chaque test anglais, et la configuration de test force `fr` au départ (tâche 1).
