# Onglet Solo et 5×15 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 5×15 (Friese) devient un jeu ludo-rs à un joueur, rangé dans un nouvel onglet Solo de l'accueil, et la carte Cryptide gagne sa légende puma/ours.

**Architecture:** Une crate `games/five-by-fifteen` implémente `Game` (1 joueur, sans information cachée) ; le registre Rust l'expose au WASM comme les autres jeux. Côté web, un champ `solo` du registre range le jeu dans l'onglet Solo (`#/solo`) ; le salon existant sert d'écran d'options sans sièges ni réseau ; le plateau reprend la version « Shinkansen Express ».

**Tech Stack:** Rust (ludo-core, serde, rand_chacha), React + Vitest, i18n maison.

**Spec:** `docs/superpowers/specs/2026-11-22-solo-tab-5x15-design.md`

## Global Constraints

- Règle source [R] : `~/prog/magic/spiral/2f-spiele_rules_5x15_US.pdf` (hors dépôt) ; décision utilisateur [U] ; version visuelle de référence : `~/prog/lepandasamuse/5x15.html` (hors dépôt, à lire, pas à copier dans le dépôt tel quel).
- `apply` renvoie `Illegal` sans modifier l'état, ne panique jamais. Messages `Illegal` en français.
- Mélange : `ChaCha8Rng::seed_from_u64(seed)`, jamais `SmallRng`, jamais `gen_range` sur un `usize` (tirer un `u32`).
- La vue ne contient jamais la graine.
- Le moteur possède toute la logique : l'écran n'a aucune règle de 5×15 (il lit `legalActions` et la vue).
- Tout texte de l'écran 5×15 et de l'onglet passe par `web/src/i18n/` (`fr.ts` référence, `en.ts` typé dessus). Le rappel de règles (`rules.ts`) et la légende Cryptide restent en français.
- Commits : `cargo fmt --all` et `cargo clippy --workspace --all-targets -- -D warnings` avant chaque commit ; email marc.camuzat@gmail.com (déjà configuré) ; message terminé par `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Légende Cryptide : rouge = puma, noir = ours (dessin actuel juste).

## Review Focus

- Un trou en colonne 1 (index 0) : seul un 2 de la couleur de l'ancre y va ; un trou à droite d'un 15 ne se remplit que par une poussée ou par la tuile −1 de sa voisine de droite.
- Une poussée déplace toute la suite maximale finissant par le 15, jamais au-delà de la colonne 15, et n'est pas offerte si la suite est plus courte que le parcours.
- Partie bloquée : le jeu finit (`Stuck`) dès qu'aucun coup n'existe, y compris après une poussée ; « Abandonner » reste toujours possible tant qu'on joue.
- Position répétée : avertissement dans la vue, le jeu continue ; « Annuler » (takeBack) puis rejeu ne doit pas faire planter (le journal se rejoue).
- Retour à l'accueil depuis une partie solo : on retombe sur l'onglet Solo, et un lien `?join=CODE` marche toujours.

**Interfaces:**
- Produces (crate `five_by_fifteen`) :
  - `pub struct FiveByFifteen;` — `meta()` : `id: "five-by-fifteen"`, `name: "5×15"`, `min_players: 1`, `max_players: 1`, `hidden_info: false`, `clock: false`.
  - `pub enum Route { Short, Medium, Long }` (serde par nom, défaut `Short`) ; `Route::min_run(self) -> usize` = 3/4/5.
  - `pub struct Config { pub route: Route }` ; `options()` = une `Choice` `key: "route"`, `values: ["Short","Medium","Long"]`, `default: "Short"`.
  - `pub enum Color { Emerald, Crimson, Azure, Amber, Violet }` ; `pub struct Tile { pub color: Color, pub number: u8 }` (2..=15 sur le plateau).
  - `pub struct Pos { pub row: u8, pub col: u8 }` ; `col` 0..=14 = colonnes 1 à 15 de la règle (la colonne zéro des « 1 » est `anchors`).
  - `pub enum Action { Place { from: Pos, to: Pos }, Shift { row: u8, to: u8 }, GiveUp }` — `Shift` : la suite qui finit par le 15 en `to - 1` avance d'une case, dans le trou `to`.
  - `pub enum Status { Playing, Won, Stuck, GaveUp }`.
  - `pub struct State { pub config: Config, pub anchors: [Color; 5], pub cells: [[Option<Tile>; 15]; 5], pub status: Status, pub moves: u32, pub repeated: bool, pub seen: BTreeSet<u64> }`.
  - `pub struct View` (`view.rs`, serde camelCase) : `route`, `minRun: u8`, `anchors`, `cells`, `status`, `moves`, `repeated`, `sorted: [u8; 5]` (nombre de tuiles bien placées depuis la gauche, 0..=14), `locomotives: Vec<Locomotive>` avec `Locomotive { row: u8, col: u8 /* col du 15 */, ready: bool }`.
  - `testing::state(anchors: [Color; 5], cells: [[Option<Tile>; 15]; 5], route: Route) -> State` (status recalculé, `seen` initialisé).

- `a_position_seen_before_is_flagged` : deux coups qui reviennent à la position de départ (aller-retour d'une tuile entre deux trous voisins compatibles) : `repeated == true` après le retour, `false` avant ; le jeu continue.
- `the_view_shows_sorted_prefix_and_locomotives` : `sorted` d'une ligne 2,3,4 puis faux = 3 ; 13-14-15 attelés : une `Locomotive` au col du 15, `ready` vrai seulement si `Shift` est légal.

- [ ] **Step 3: Implémenter**

- `new` : 75 tuiles (couleur × 1..=15) mélangées par `ChaCha8Rng` (Fisher-Yates à tirages `u32`) sur 5 × 15 ; les « 1 » sortent, leurs couleurs, remélangées, deviennent `anchors` ; leurs cases restent `None`. `seen` reçoit le hachage de départ.
- Hachage de position : FNV-1a 64 bits écrit à la main sur les 75 cases (`None` = 0, sinon `color * 16 + number`) : stable entre wasm32 et natif. Après chaque coup : `repeated = !seen.insert(h)`.
- Voisin gauche d'une case `col 0` = l'ancre (« 1 » de sa couleur). Poussée : suite maximale de même couleur, nombres consécutifs, adjacente, finissant par le 15 en `to - 1`, longueur ≥ `min_run`, `to <= 14`.
- Après un coup : `Won` si chaque ligne a 2..=15 de la couleur de son ancre en `col 0..=13` ; sinon `Stuck` si aucun `Place`/`Shift`.
- `pending` : `Seat(0)` tant que `Playing`. `outcome` : `Ranked(vec![0])` dès que fini.
- `Determinize` : identité. `Heuristics` : `rollout_action` = `GiveUp` si `moves >= 400`, sinon un coup tiré uniformément hors `GiveUp` ; `budget` → `None`.
- `RULES.md` : règle [R] citée ; [U] la boucle (avertissement au lieu de « perdu »), « Abandonner » ; choix des noms de couleurs et des parcours.
