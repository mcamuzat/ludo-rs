# Black-Pot Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ajouter Black-Pot (alignements et calcul mental aux 3 dés, 2 joueurs ou 4 en équipes) à ludo-rs, jouable contre l'IA et en ligne.

**Architecture:** Une crate `games/black-pot` (structure de `games/bantu`) : plateau statique, calculs (`Expr`), alignements, règles, vue, IA ISMCTS restreinte par `search_actions`. Le site dessine le plateau d'après un `board.json` produit par un test, et le joueur compose son calcul sans que rien ne soit calculé côté client.

**Tech Stack:** Rust 2021 (`rand` 0.8, `rand_chacha` 0.3, `serde`), React + TypeScript (Vitest).

**Spec:** `docs/superpowers/specs/2026-10-21-black-pot-design.md` (à lire en entier avant chaque tâche).

## Global Constraints

- id du jeu `black-pot`, nom affiché « Black-Pot », crate `black-pot` (module Rust `black_pot`), type `BlackPot`, 2 ou 4 joueurs (`min_players: 2`, `max_players: 4`, 3 refusé par `check_config`), `hidden_info: true`, `clock: true`.
- `ludo-core` et `games/*` restent natifs : jamais de `wasm-bindgen`, `js-sys`, `web-sys`.
- Hasard : `ChaCha8Rng` seulement (jamais `SmallRng`), tirer des `u32` (jamais `gen_range` sur `usize`). La graine ne va jamais dans une vue.
- `apply` renvoie `Illegal` sans modifier l'état et ne panique jamais, quelle que soit l'entrée (indices de dés hors bornes, cases hors bornes, expressions absurdes).
- La vue ne contient **pas** la liste des coups légaux. Le Board n'utilise `legalActions` que pour savoir s'il est au trait.
- `RULES.md` cite [R], [B] ou [U] pour chaque règle ; ❓ pour ce qui est déduit (liste au §9 de la spec).
- Messages et textes affichés en français.
- Avant chaque commit : `cargo fmt --all` et `cargo clippy --workspace --all-targets -- -D warnings` ; tests ciblés `cargo test --release -p black-pot`.
- Commits avec l'e-mail du dépôt (`marc.camuzat@gmail.com`, déjà configuré localement), terminés par `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. Un invité en ligne envoie un calcul faux : il doit voir le message du moteur, pas une erreur générique ni rien (vérifier le chemin `onError` pour l'hôte et pour l'invité, Task 7).
2. Le dernier pion d'un camp est posé au milieu d'un tirage partagé à 4 : la partie s'arrête aussitôt, les autres ne jouent pas ce tirage (test Task 4).
3. Un camp à qui il reste 1 ou 2 pions : les coups qui en posent plus sont refusés et absents des coups légaux, et le coup à 0 pion reste permis (test Task 4).
4. Un humain dont le seul coup légal serait `NotFound` n'existe pas : quand aucun `Play` n'existe, le moteur passe tout seul (test Task 4 : jamais un `pending` dont les coups légaux sont réduits à `[NotFound]`).
5. Le Board reçoit une nouvelle vue (nouveau tirage, coup refusé) : le calcul en cours est gardé après un refus, et effacé quand le tirage ou le joueur au trait change (test Task 7).

### Task 2: Calculs

**Files:**
- Create: `games/black-pot/src/calc.rs`, `games/black-pot/tests/calc.rs`

**Interfaces:**
- Produces :
  - `#[derive(Clone, Copy, Debug, PartialEq, Eq, Hash, Serialize, Deserialize)] pub enum Op { Add, Sub, Mul, Div }`
  - `#[derive(Clone, Debug, PartialEq, Eq, Hash, Serialize, Deserialize)] pub enum Expr { Die(u8), Op { op: Op, left: Box<Expr>, right: Box<Expr> } }` (JSON : `{"Die":0}`, `{"Op":{"op":"Add","left":…,"right":…}}`) ; `Die(i)` désigne le dé d'indice `i` du tirage.
  - `pub fn dice_used(expr: &Expr) -> Vec<u8>` (indices, dans l'ordre de lecture)
  - `pub fn eval(expr: &Expr, dice: &[u8; 3]) -> Result<u32, Illegal>` : refuse un indice ≥ 3, un résultat intermédiaire négatif (« 2 − 6 donne un nombre négatif »), une division inexacte (« 7 ÷ 2 ne tombe pas juste ») ou par 0 (« on ne divise pas par 0 »), une profondeur supérieure à 2 opérations (« un calcul emploie au plus 3 dés »).
  - `pub fn announce(expr: &Expr, dice: &[u8; 3]) -> Result<String, Illegal>` : texte annoncé, en enchaînement comme dans [R]. Un dé seul : `"4"`. Une paire : `"6 − 4 = 2"`. Un triple `(a∘b)∘c` : `"6 × 4 = 24 ÷ 2 = 12"`. Un triple `c∘(a∘b)` dont l'opération extérieure est commutative s'annonce comme `(a∘b)∘c`. Sinon : `"4 − 2 = 2, 6 ÷ 2 = 3"`. Signes `+ − × ÷` (U+2212, U+00D7, U+00F7).
  - `pub fn values(dice: &[u8; 3], group: &[u8]) -> BTreeMap<u32, Expr>` : chaque valeur atteignable par le sous-ensemble `group` d'indices (1 à 3, tous employés), avec un calcul représentatif fixe (le premier trouvé dans un ordre d'énumération déterministe : opérations dans l'ordre `Add, Sub, Mul, Div`, gauche avant droite).

- [ ] **Step 1: Tests** dans `tests/calc.rs` : avec `[4, 2, 6]` :
  - `eval` de `6 − 4` = 2, de `(6 × 4) ÷ 2` = 12, de `6 ÷ (4 − 2)` = 3, de `(2 + 4) − 6` = 0 ;
  - `eval` de `2 − 6` est `Err` ; avec `[6, 3, 3]`, `6 ÷ (3 − 3)` est `Err` ; avec `[5, 2, 1]`, `5 ÷ 2` est `Err` ;
  - `announce` donne exactement `"6 × 4 = 24 ÷ 2 = 12"`, `"4 − 2 = 2, 6 ÷ 2 = 3"`, et `6 + (4 × 2)` s'annonce `"4 × 2 = 8 + 6 = 14"` ;
  - `values([4,2,6], &[0,1,2])` contient 0, 3, 12, 14 et aucune valeur Black-Pot n'apparaît dans `values` d'une paire, pour tout tirage (boucle sur les 216 tirages et toutes les paires) ;
  - `values(d, &[i])` = `{d[i]}`.

  - `pub struct State` (`Clone, Debug, Serialize, Deserialize`) : `players`, `owner: Vec<Option<u8>>`, `counted: Vec<[bool; 4]>`, `pawns_left: [u8; 2]`, `alignments: Vec<Alignment>`, `dice: [u8; 3]`, `roller: Seat`, `queue: Vec<Seat>` (qui doit encore jouer ce tirage, en tête celui qui joue), `last: Vec<Option<TurnRecord>>` (par siège), `quiet: u32` (tours de joueur de suite sans pion posé), `turns: u32`, `seed: u64`, `rolls: u32`, `end: Option<End>`.
  - `pub fn score(s: &State, team: u8) -> u32` (alignements + 10 × pions restants)
  - `pub fn plays(s: &State, seat: Seat) -> Vec<Action>` : les `Play` canoniques (un par ensemble trié de cases occupées, coup à 0 pion compris ; partitions dans l'ordre `{012}`, `{01}{2}`, `{02}{1}`, `{12}{0}`, `{0}{1}{2}`, valeurs par `calc::values`, cases libres de cette valeur dans l'ordre des id, toutes distinctes ; pas plus de cases que de pions restants).
- Comportement :
  - **Tirage** : le tirage numéro `k` = 3 `u32` de `ChaCha8Rng::seed_from_u64(seed ^ (u64::from(k) * 0x9E37_79B9_7F4A_7C15))`, chacun `% 6 + 1`. `new` tire le premier lanceur (`u32 % players`) d'un `ChaCha8Rng::seed_from_u64(seed)` séparé, puis lance.
  - **File** : à 2 joueurs `[roller]` ; à 4, `[roller+1, roller+2, roller+3, roller]` (mod 4). Quand elle est vide, `roller` avance d'un siège, nouveau tirage.
  - **Passage automatique** : après chaque action (et dans `new`), tant que la tête de file n'a aucun `Play`, on enregistre `Passed`, on la retire et `quiet += 1` ; `quiet ≥ QUIET_ROUNDS × players` termine en `QuietLimit`. Ce passage est borné (la limite de durée garantit la fin).
  - `legal_actions` : `plays` + `NotFound` si `plays` est non vide ; vide hors du trait.
  - `apply(Play)` vérifie, sans rien modifier en cas d'erreur : au trait ; chaque dé employé exactement une fois sur l'ensemble des groupes ; `eval` réussit ; `cell == None` ⇔ valeur 0 ; case existante, libre, de cette valeur, différente des autres groupes ; assez de pions. Puis pose, calcule `new_alignments` pour l'équipe, marque `counted`, enregistre `Played` (textes par `announce`), remet `quiet` à 0 si au moins un pion est posé, sinon `+1`. Message pour un mauvais total : `"{annonce}, pas {valeur de la case}"`.
  - `apply(NotFound)` : légal seulement si `plays` est non vide ; `quiet += 1`.
  - **Fin** : dès que `pawns_left[team] == 0`, `End::AllPlaced`, file vidée. `outcome` : rangs par score décroissant, égalités partagées, coéquipiers au même rang.
  - `timeout_action` : `NotFound` (ou `None` hors du trait).
  - `check_config` refuse 3 joueurs (« Black-Pot se joue à 2 ou à 4. »).
- `testing.rs` : `pub fn position(players: u8, owners: &[(CellId, u8)], dice: [u8; 3], queue: &[u8]) -> State` (pions posés non comptés, pions restants décomptés).
