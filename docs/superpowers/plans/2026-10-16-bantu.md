# Bantu — plan d'implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal :** ajouter Bantu (`bantu`, Parker Brothers 1955, 2–4 joueurs, sans hasard) jouable contre l'IA et en ligne.

**Architecture :** une crate `games/bantu` calquée sur `games/yavalath`. Le plateau est un graphe généré une fois depuis le PDF : les pages 4 à 7 sont **vectorielles**, donc on extrait les cercles et les liaisons exactement au lieu de les relever à l'œil. Les règles portent sur ce graphe. Le site dessine le plateau en SVG d'après les données du moteur.

**Tech Stack :** Rust (ludo-core), Python 3 stdlib (extraction, script ponctuel), React/TypeScript (vitest).

**Spec :** `docs/superpowers/specs/2026-10-16-bantu-design.md`.

## Global Constraints

- Règles du `CLAUDE.md` du dépôt : `apply` renvoie `Illegal` sans modifier l'état ; jamais de `wasm-bindgen` dans `games/*` ; mettre à jour `web/src/games/bantu/types.ts` en même temps que tout type sérialisé.
- Le PDF et le GIF de l'utilisateur (`~/Téléchargements/bantu_rg.pdf`, `bantu_01.gif`) ne sont **jamais copiés** dans le dépôt. Seules les données extraites (coordonnées et liaisons) y entrent.
- 2 à 4 joueurs ; option `short` (pions 1 à 3), désactivée par défaut.
- Limite de durée : 30 tours de table sans arrivée ni prise, ou personne ne peut bouger → fin. Classement : pions arrivés (décroissant), puis avancement (somme des plus courts chemins restants, croissant).
- **Point d'arrêt** après la tâche 1 : l'utilisateur valide l'image du plateau avant la suite.
- Commits avec l'e-mail du dépôt, terminés par `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>` ; `cargo fmt --all` et `cargo clippy --workspace --all-targets -- -D warnings` avant chaque commit.

## Review Focus

1. Un pion qui glisse dans sa rangée ne doit jamais repasser par une case déjà traversée pendant le même coup. Test dans la tâche 2 (`no_cell_twice_in_one_move`).
2. Une rangée qui contient des pions de plusieurs couleurs fait avancer chaque pion de la somme, et les protège tous. Test dans la tâche 2 (`mixed_row_sums_and_protects`).
3. Un joueur sans coup ne bloque pas la table : son tour passe, et si plus personne ne peut jouer, la partie s'arrête. Tests dans la tâche 2 (`a_seat_without_move_is_skipped`, `nobody_can_move_ends_the_game`).
4. Un aller-retour sans fin arrête la partie au 30e tour de table, et une prise remet le compteur à zéro. Test dans la tâche 2 (`quiet_limit_ends_the_game`).
5. On ne peut ni entrer sur une case occupée de la ligne de départ, ni y prendre (les lignes de départ protègent). Test dans la tâche 2 (`enter_only_on_a_free_start_cell`).

**Files :**

- Modify : `Cargo.toml` du workspace (`members` et `bantu = { path = "games/bantu" }`)

**Interfaces :**
- Produces (dans `board`) :
  - `pub type Cell = u8;` (index dans `CELLS`)
  - `pub struct CellDef { pub x: i16, pub y: i16, pub arrow: bool }`, coordonnées dans un repère 0..1000 de l'image entière (ligne 1 en bas, 4 à gauche, arrivée en bas à gauche) ;
  - `pub static CELLS: &[CellDef]` ;
  - `pub static START_LINES: [[Cell; 4]; 4]` : `START_LINES[n - 1]` est la ligne du pion n, les cases dans leur ordre le long de la ligne ;
  - `pub static ROWS: &[&[Cell]]` : les rangées marron, dans leur ordre ; deux cases voisines d'une rangée ou d'une ligne se joignent dans les deux sens ;
  - `pub static LINKS: &[(Cell, Cell)]` : les liaisons bleu clair, **orientées** dans le sens du parcours ;
  - `pub enum Group { Start(u8), Row(u16), Single }` et `pub fn group(cell: Cell) -> Group` ;
  - `pub fn neighbours(cell: Cell) -> impl Iterator<Item = Cell>` : les liaisons sortantes, plus les voisines de rangée ou de ligne ;
  - `pub fn distance_to_finish(cell: Cell) -> u8` : le plus court chemin en pas jusqu'à l'arrivée (1 depuis une case fléchée), précalculé.

L'extraction : `pdftocairo -svg -f N -l N` sur chaque page de 4 à 7, puis analyse XML (stdlib, `python3 -I`). Le contenu des pages se reconnaît à sa couleur :
- cercles : remplissage `rgb(60%, 80%, 100%)` et chemin fermé en arcs ; le centre est le milieu de la boîte ;
- rangées : remplissage `rgb(50.2%, 0.4%, 0.4%)` ; une case appartient à la rangée dont le polygone contient son centre ;
- lignes de départ : remplissage `rgb(100%, 0.4%, 0.4%)` ;
- liaisons bleu clair : traits de même couleur que les cercles, reliant deux centres ;
- flèches : remplissage `rgb(20.4%, 40.4%, 100%)` ;
- disque central : remplissage `rgb(60%, 20.4%, 0.4%)`.

Chaque page est un quart découpé (clip) : on ramène les quatre au même repère grâce au disque central commun, puis on fusionne les cercles en double à la jonction des quarts. Le sens de chaque liaison se déduit du sens horaire : les flèches bleues orientent les liaisons qu'elles portent, et les autres vont de la ligne de départ N vers la suivante (4 → 3 → 2 → 1 → arrivée), ce qui fixe un ordre de progression le long de chaque quart. Les cases fléchées sont celles qui contiennent une flèche bleue près de « FINISH ». Tout ce que le script ne sait pas trancher, il l'affiche, et le builder le règle à la main dans le script (table d'exceptions commentée), jamais dans le fichier généré.

### Task 2 : règles

**Files :**
- Modify : `games/bantu/src/lib.rs`
- Create : `games/bantu/src/moves.rs` (longueurs, chemins, protections), `games/bantu/RULES.md`, `games/bantu/tests/rules.rs`, `games/bantu/src/testing.rs` (positions construites à la main)

**Interfaces :**
- Consumes : `board` (tâche 1).
- Produces :
  - `pub struct Bantu;` ; `Config { short: bool }` (`#[serde(default)]`), avec `options()` = `Toggle { default: false }` sur `short` ;
  - `#[serde(tag = "kind")] pub enum Spot { Home, On { cell: Cell }, Finished }` ;
  - `pub enum Dest { Cell(Cell), Finish }` ; `pub enum Action { Move { piece: u8, to: Dest } }` (une seule variante, mais un enum pour pouvoir l'étendre) ;
  - `pub enum End { Won(Seat), QuietLimit, Blocked }` ;
  - `State { config, players: u8, pieces: Vec<Vec<Spot>>` (siège × pion, index = numéro − 1), `turn: Option<Seat>, quiet: u32, last: Option<LastMove>, end: Option<End> }` et `LastMove { seat, piece, from: Spot, to: Spot, captured: Option<(Seat, u8)> }` ;
  - `pub const QUIET_ROUNDS: u32 = 30;`
  - `pub fn move_length(s: &State, seat: Seat, piece: u8) -> u8` ; `pub fn is_protected(s: &State, cell: Cell) -> bool` ; `pub fn progress(s: &State, seat: Seat) -> (u8, u32)` (pions arrivés, somme des distances ; un pion à `Home` compte 1 + la plus petite `distance_to_finish` des cases de sa ligne) ;
  - `testing::position(players: u8, pieces: &[(u8 /*seat*/, u8 /*piece*/, Spot)], turn: u8) -> State`.

Génération des coups d'un pion sur une case : parcours en profondeur depuis sa case, avec exactement `move_length` pas sur `board::neighbours`, sans repasser par une case du chemin, sans traverser de case occupée. La destination doit être libre, ou porter un pion adverse non protégé. Atteindre une case fléchée avec au moins un pas restant ajoute `Dest::Finish`. Un pion à `Home` peut aller sur toute case libre de `START_LINES[piece - 1]`. Après chaque coup, le tour passe au siège suivant qui a un coup ; chaque siège sauté compte dans `quiet`. Une arrivée ou une prise remet `quiet` à 0. La partie s'arrête sur `Won` (tous les pions d'un siège arrivés), sur `QuietLimit` (`quiet >= QUIET_ROUNDS * players`) ou sur `Blocked` (aucun siège n'a de coup). `outcome` classe toujours par `progress` : arrivés décroissant, puis distance croissante, les égalités partageant leur rang.
