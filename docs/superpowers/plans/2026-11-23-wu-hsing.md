# Wu Hsing multijoueur — plan d'implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal :** Wu Hsing (Sackson), règle de base, 2–4 joueurs, humains et IA, sur ludo-rs, avec une aide à la pose qui montre les emplacements légaux.

**Architecture :** une crate `games/wu-hsing` (règles, vue, déterminisation, IA) branchée dans `ludo-registry`. Le plateau n'a pas de bord : les dominos posés sont rangés dans une liste sérialisée, avec un index de cases reconstruit en mémoire. Le moteur énumère les poses légales et leurs points ; le web (`web/src/games/wu-hsing/`) les affiche.

**Tech Stack :** Rust (ludo-core, rand 0.9 + `rand_chacha`, serde), React + TypeScript + vitest.

**Spec :** `docs/superpowers/specs/2026-11-23-wu-hsing-design.md`. Référence d'implémentation : `~/prog/magic/domino/js/rules.js` et `test/rules.test.js` (hors dépôt, à lire). Règle : `~/prog/magic/domino/wuhsi_rg.pdf` p. 2–3.

## Global Constraints

- Mélanges avec `ChaCha8Rng` seulement ; ne jamais tirer un `usize` (`gen_range(0..v.len())`), tirer un `u32` et le convertir.
- `apply` renvoie `Illegal` (message français, tutoiement) sans toucher l'état ; ne panique jamais sur une entrée.
- `view` ne contient jamais la graine, les mains adverses ni le domino écarté à 3 joueurs.
- `shared_screen` faux (mains secrètes) ; `hidden_info: true`.
- Règle de base seulement, aucune option de partie.
- Tout changement de type sérialisé met à jour `web/src/games/wu-hsing/types.ts` dans le même commit.
- `cargo fmt --all` et `cargo clippy --workspace --all-targets -- -D warnings` avant chaque commit.
- Commits avec `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`, email `marc.camuzat@gmail.com`.
- Textes du plateau en français (le jeu n'est pas traduit) ; aucun nouveau texte hors plateau.

## Review Focus

1. Deux dominos de mêmes valeurs dans une main, ou un double : un seul coup listé par plateau obtenu, et `apply` refuse la forme non canonique (Task 3, test `twins_and_doubles_are_listed_once`).
2. Le joueur qui vide sa main n'est pas le premier : la partie s'arrête quand le tour revient au premier joueur, pas au finisseur (Task 3, test `the_round_ends_at_the_first_player`).
3. Un joueur bloqué pendant que les autres jouent : `Pass` n'est légal que sans pose possible, le compteur de passes se remet à zéro à chaque pose, la partie s'arrête quand tous ont passé à la suite (Task 3, tests `pass_only_when_stuck`, `all_passing_ends_the_game`).
4. Un état rejoué depuis JSON (journal, P2P) : l'index de cases se reconstruit, les coups légaux sont identiques (Task 2, test `board_survives_a_json_round_trip`).
5. Le plateau grandit loin de l'origine (coordonnées négatives) : rendu et coups légaux corrects (Task 2, test `negative_coordinates_work` ; Task 5, test « draws dominoes left of and above the start »).

**Files :**

**Interfaces :**

  - `#[derive(Clone, Copy, Debug, PartialEq, Eq, Hash, Serialize, Deserialize)] pub struct Placement { pub domino: u8, pub row: i8, pub col: i8, pub dir: Dir, pub flipped: bool }` — l'ancre `(row, col)` reçoit `a` (ou `b` si `flipped`), l'autre case l'autre valeur.
  - `#[derive(Clone, Copy, Debug, PartialEq, Eq, Serialize, Deserialize)] pub struct Placed { pub at: Placement, pub by: Option<u8> }` — `by: None` pour le carré de départ.
  - `pub struct Board` avec `#[serde(from = "Vec<Placed>", into = "Vec<Placed>")]` : liste des dominos posés + index `(i8, i8) → (valeur, indice dans la liste)` reconstruit à la désérialisation (`HashMap` ou autre, au choix ; jamais itéré pour produire un ordre visible).
  - `impl Board { pub fn new(starters: [u8; 2]) -> Board; pub fn placed(&self) -> &[Placed]; pub fn value_at(&self, row: i8, col: i8) -> Option<u8>; pub fn evaluate(&self, p: &Placement) -> Result<u32, Illegal>; pub fn place(&mut self, p: Placement, by: u8); pub fn moves(&self, dominoes: &[u8]) -> Vec<(Placement, u32)> }`
  - `pub fn valid_cycle(values: &[u8]) -> bool`
- Carré de départ : `starters[0]` horizontal en `(0,0)`, `starters[1]` horizontal en `(1,0)`, non retournés.
- `evaluate` porte `evaluatePlacement` + `violatesFourInLine` du JS, dans le même ordre de contrôles, avec ces messages :
  - cases occupées : « Ces cases ne sont pas libres. »
  - cycle cassé : « Ce placement casse un cycle de couleurs. »
  - moins de 2 groupes : « Ce domino doit prolonger au moins deux groupes. »
  - règle 2 : « Quatre dominos alignés par leur grand côté : interdit. »
  - points : produit des longueurs des groupes comptés (ligne propre seulement si > 2 ; perpendiculaire si ≥ 2), ×2 pour un double.
  - Règle 2 comme le JS : on compte les dominos de même orientation **exactement alignés** (même colonne pour des horizontaux sur des rangées consécutives, même rangée pour des verticaux sur des colonnes consécutives).
- `moves` : pour chaque domino donné, chaque emplacement dont au moins une case est vide et voisine d'une case occupée, les deux sens, `flipped` faux et vrai (faux seulement pour un double), garder ceux que `evaluate` accepte. Ordre déterministe : domino, puis `(row, col)`, puis `dir`, puis `flipped`. Coordonnées hors de `i8` ignorées sans paniquer.

  - `#[derive(Clone, Copy, Debug, PartialEq, Eq, Hash, Serialize, Deserialize)] pub enum Action { Place(Placement), Pass }`
  - `#[derive(Clone, Debug, Default, PartialEq, Eq, Serialize, Deserialize)] pub struct Config {}`
  - `pub struct State { pub board: Board, pub hands: Vec<Vec<u8>>, pub discarded: Option<u8>, pub scores: Vec<i32>, pub first: Seat, pub turn: Option<Seat>, pub passes: u8, pub last_round: bool, pub last: Option<(Seat, Action, u32)>, pub finish: Option<Finish> }`
  - `pub struct Finish { pub penalties: Vec<i32>, pub totals: Vec<i32> }`
  - `impl State { pub fn moves(&self, seat: Seat) -> Vec<(Action, u32)> }` — poses légales avec leurs points, `[(Pass, 0)]` si aucune ; vide si `seat` n'est pas au trait. Partagé par `legal_actions`, la vue et l'IA.
  - `GameMeta { id: "wu-hsing", name: "Wu Hsing", min_players: 2, max_players: 4, hidden_info: true, clock: true }` ; `timeout_action` : la pose qui rapporte le plus (ou `Pass`).
- Coups canoniques : `moves` ne passe à `Board::moves` que le plus petit id de chaque paire de valeurs de la main ; `apply` refuse un id jumeau non canonique (« Joue le premier de tes deux dominos identiques. ») et un double retourné.
- Fin : après chaque action, si la main du joueur est vide, `last_round = true`. Siège suivant = `(seat + 1) % n`. La partie s'arrête si `last_round` et que le suivant est `first`, ou si `passes == n` (`passes` remis à 0 à chaque pose). À la fin : `penalties[i] = 5 × doubles + 25 × autres` en main, `totals = scores − penalties`, `turn = None`.
- `outcome` : rang par `totals` décroissant, égalités au même rang.
- `apply(Pass)` alors qu'une pose existe : `Illegal("Un coup est possible : tu ne peux pas passer.")`.
- `View` (`view.rs`, `#[serde(rename_all = "camelCase")]`) :
  - `me: Option<Seat>`, `placed: Vec<PlacedView>` avec `PlacedView { row: i8, col: i8, dir: Dir, first: u8, second: u8, by: Option<u8> }` (`first` = valeur sur l'ancre)
  - `hand: Vec<HandDomino { id: u8, a: u8, b: u8 }>` (vide pour un spectateur), `hand_sizes: Vec<u8>`, `scores: Vec<i32>`, `turn: Option<Seat>`, `first: Seat`, `last_round: bool`
  - `last: Option<LastMove { seat: Seat, placed: Option<usize>, points: u32 }>` (`placed` = indice dans `placed`, `None` pour une passe), `finish: Option<Finish>`
  - `legal: Vec<LegalMove { action: Action, points: u32 }>` : `state.moves(me)` si `me` est au trait, sinon vide.
- `determinize(s, observer)` : rassembler les mains des autres sièges et `discarded`, mélanger avec `rng`, redistribuer aux mêmes tailles (mains triées).
- `RULES.md` : règles de la section « Règles » du spec, sourcées **[R]** François Haffner, adaptation française de Sid Sackson, *A Gamut of Games*, janvier 2004 (copie de l'utilisateur `wuhsi_rg.pdf`, hors dépôt) ; mentionner la correction de fin de partie par rapport au JS.

### Task 5 : plateau web

**Files :**

**Interfaces :**
- Consumes : la `View` et `Action` de Task 3, sérialisées par serde (`Action` = `{ Place: { domino, row, col, dir: "Right" | "Down", flipped } } | "Pass"`).
- Produces : `export function WuHsingBoard(props: BoardProps)`, `export function finishText(f: Finish, names: string[]): string`.

Comportement :
- Couleurs et points des valeurs repris du JS : 1 Bois `#3f9142`, 2 Feu `#d1453b`, 3 Terre `#d9a441`, 4 Métal `#9fb0bb`, 5 Eau `#34599c` (points : `PIP_MAP` du JS). Le carré de départ est neutre, chaque domino posé porte un liseré de la couleur de son joueur, et le dernier coup est mis en évidence.
- Grille : boîte englobante des cases occupées, plus 2 cases de marge de chaque côté, à taille de case fixe dans un conteneur qui défile (pas de défilement horizontal de la page).
- Aide à la pose, clé locale `wu-hsing.aid`, valeurs `"none" | "playable" | "places"`, défaut `"places"`, lecture et écriture sous try/catch. Sélecteur à trois boutons au-dessus de la main : « Aide : aucune / dominos jouables / emplacements ».
- Interaction, identique dans tous les modes : on choisit un domino de la main, un toucher sur une case affiche l'aperçu (fantôme) d'une pose qui couvre cette case, et un toucher sur l'aperçu la confirme (`submit`). Les boutons « Tourner » (`R`) et « Retourner » (`F`) changent l'aperçu.
  - *places* : les cases couvertes par au moins une pose légale du domino choisi sont surlignées. L'aperçu ne propose que des poses légales couvrant la case touchée, et « Tourner » / « Retourner » passent de l'une à l'autre. Les points s'affichent sur l'aperçu.
  - *playable* : les dominos de la main qui ont au moins une pose dans `legal` sont marqués. L'aperçu suit le sens et le retournement courants et affiche « légal, N points » ou « illégal ».
  - *none* : comme *playable*, sans marquage de la main.
  - La légalité se lit dans `view.legal`, en comparant les valeurs du domino (et non son id, pour couvrir le jumeau non canonique). Le coup envoyé est l'action de `legal` correspondante.
- Bouton « Passer » toujours actif au trait : il envoie `"Pass"`, et le moteur refuse s'il existe un coup.
- Bandeau : scores, nombre de dominos par joueur, « dernier tour » si `lastRound`. En fin de partie : `finishText` (gagnant, totaux, pénalités).
- `rules.ts` : 5 ou 6 lignes d'accord avec `RULES.md`.
