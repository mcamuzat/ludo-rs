# Monad Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Monad (Sid Sackson, 3M 1970) jouable sur ludo-rs (contre l'IA, sur le même écran, en ligne), 2 à 4 joueurs.

**Architecture:** Une crate `games/monad` (matériel, règles, vue, déterminisation, IA) qui implémente `Game`, `Determinize` et `Heuristics` de `ludo-core`, inscrite dans `ludo-registry` ; un plateau React dans `web/src/games/monad/` qui n'affiche que la `View` et apparie la sélection du joueur avec `legalActions`.

**Tech Stack:** Rust 2021 (`ludo-core`, `serde`, `rand`/`rand_chacha`), React 19 + Vitest.

**Spec:** `docs/superpowers/specs/2026-10-19-monad-design.md`

## Global Constraints

- Identifiant `monad`, nom affiché « Monad », 2 à 4 joueurs, `hidden_info: true`, `clock: true`, aucune option (`Config` vide, `#[serde(default)]`, lit `null` et `{}`).
- Couleurs, dans l'ordre de référence : rouge, orange, jaune (chaudes), marine, ciel, vert (froides). Combinaisons Bonus : rouge/marine, orange/ciel, jaune/vert.
- Valeurs : Unité 1, Bi 3, Tri 7, Quad 16, Quint 36, Monade 80. 10 Monades.
- Mise en place : 2 joueurs 12 Unités (2 par couleur), 2 Identités tirées parmi les 6 ; 3 joueurs 18 Unités, Identités marine/ciel/vert ; 4 joueurs 24 Unités, Identités rouge/orange/marine/ciel. 6 Unités par main, ni pioche ni défausse.
- Monades pour gagner : 5 à 2 joueurs, 4 à 3, 3 à 4.
- Accaparer : seulement **après** au moins un échange ou un achat dans le même tour ([M], choix de l'utilisateur).
- Achat : seulement sans carte superflue (retirer n'importe quelle carte fait passer sous la valeur), au moins 2 cartes, toutes de rang strictement inférieur à la cible.
- Limites : fin si un tour de table entier n'est fait que de `Pass` ; fin après 40 tours de table (40 × joueurs tours) sans Monade prise ; classement alors par Monades seules.
- Hasard uniquement à la mise en place, avec `ChaCha8Rng::seed_from_u64(seed)` ; tirer des `u32`, jamais des `usize`. Rien du hasard n'est gardé dans l'état.
- `apply` renvoie `Illegal` sans modifier l'état et ne panique jamais ; il accepte exactement `legal_actions`.
- `games/monad` ne dépend jamais de `wasm-bindgen`, `js-sys`, `web-sys`.
- Rien n'est calculé côté web hormis l'appariement sélection ↔ action légale.
- Commits avec l'e-mail du dépôt (config locale), terminés par `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Avant chaque commit Rust : `cargo fmt --all` et `cargo clippy --workspace --all-targets -- -D warnings`.
- Les PDF sources ne sont jamais copiés dans le dépôt.

## Review Focus

- Bonus dont certaines parts manquent (colonne vide, pioche vide) : les parts présentes sont prises, les autres perdues ; aucun bonus proposé si rien n'est disponible. → test `bonus_skips_empty_parts` (Task 2).
- Joker : deux cartes de même rang dont l'une a la couleur d'Identité = échange ordinaire avec bonus ; Joker + carte d'un autre rang = échange au rang de l'autre carte, sans bonus ; deux cartes de rangs différents sans Joker refusées. → test `joker_trades_follow_the_other_card` (Task 2).
- Victoire au milieu d'un tour (Monade obtenue par échange, achat ou bonus impossible, mais par échange puis tour pas fini) : partie finie aussitôt, `pending` vide. → test `reaching_the_target_ends_at_once` (Task 2).
- Passer : refusé dès qu'un échange, une pioche, un retournement ou un achat « deux cartes du rang inférieur + complément » est possible, permis sinon même si un autre achat existe. → test `pass_only_when_the_rule_allows` (Task 2).
- Information cachée : une Unité piochée ou prise en bonus n'apparaît qu'au preneur ; la vue d'un adversaire donne des nombres par rang. → conformance + test `drawn_units_are_private` (Task 3).

Règles à appliquer (spec §4) :
- Échange : une chaude et une froide ; même rang r, ou une carte Joker (couleur d'Identité, rang ≥ Bi) et une autre carte de rang r ; cible `r.next()`, qui doit être disponible (colonne non vide / stock > 0). Unités cédées → `discard` ; autres → bas de leur colonne, dans l'ordre de référence.
- Bonus : échange sans Joker, r ≥ Bi, couleurs partenaires, `!bonus_used`, au moins une part disponible → `bonus_offer = Some(r)` et seuls `TakeBonus`/`DeclineBonus` sont légaux. `TakeBonus` : haut de chaque colonne de rang Bi..r−1 non vide, plus une Unité de la pioche si elle existe (`drawn`) ; `bonus_used = true`.
- Achat : sous-multiensembles minimaux (≥ 2 cartes, rang < cible, total ≥ valeur, total − plus petite valeur < valeur), sans doublon, cible disponible. Énumération récursive sur les cartes distinctes avec leur multiplicité, coupée dès que le total atteint la valeur.
- Accaparer : `turn.prepared` ; 4/5/6 Unités de couleurs distinctes → haut des Tri/Quad/Quint s'il existe.
- `prepared = true` après un échange ou un achat ; `transacted = true` après toute transaction ; `passes = 0` après tout sauf `Pass` (`passes += 1`, `stalled = true` si `passes == players`).
- Monade prise (échange de Quint ou achat) : `monads[seat] += 1`, `monad_stock -= 1`, `turns_since_monad = 0` ; si `monads[seat] >= monads_to_win` → `winner = Some(seat)`, fin immédiate.
- Passer (`may_pass`) : aucun échange, ni pioche, ni défausse, et pour aucune cible disponible T le joueur n'a deux cartes du rang immédiatement inférieur à T avec un total de ses cartes de rang < T ≥ valeur de T.
- `timeout_action` : `DeclineBonus` si offre ; sinon `EndTurn` si légal ; sinon `Draw`, `Flip`, `Pass` dans cet ordre ; sinon la première action légale.
