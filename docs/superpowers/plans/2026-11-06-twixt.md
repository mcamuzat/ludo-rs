# TwixT Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** TwixT (Little Golem "PP" rules) in ludo-rs, with twixtbot's neural network ported to Rust/WASM for a strong AI and an on-demand numeric coach plus a post-game review.

**Architecture:** New crate `games/twixt`. The board mirrors twixtbot's representation exactly (pegs and 8 link planes indexed as in `twixt.py`), so the network inputs can be checked bit for bit against Python. `net.rs` is a pure-Rust forward pass over float16 weights exported once by a Python script; `mcts.rs` is a PUCT search run through a new generic `Heuristics::own_search` hook; `coach.rs` computes every coach number. The web loads the weights lazily into the AI workers only.

**Tech Stack:** Rust (ludo-core, wasm-bindgen 0.2.121, `simd128`), React/TypeScript (Vite), Python 3 + PyTorch through `uv` for the one-off export.

**Spec:** `docs/superpowers/specs/2026-11-06-twixt-design.md`

**Upstream reference (read-only, MIT):** clone `https://github.com/stevens68/twixtbot-ui` outside the repo (e.g. in a scratch dir). Files cited below as `[UI] path` are in it: `src/backend/twixt.py`, `naf.py`, `torchmodel.py`, `nneval.py`, `nnmcts.py`, `nnmplayer.py`, `swapmodel.py`, `model/torch.pt`. Never copy the clone into the repo; port the logic.

## Global Constraints

- Rules: 24×24 board without corners; pegs of a colour never in the opponent's border rows; links auto-made to every own peg at knight distance unless they cross an **opponent** link; own links may cross; links never removed; swap on the second player's first move; win = chain between own borders; draw as soon as neither colour can still connect. No time limit.
- Seat 0 = Rouge = twixtbot `WHITE` (moves first, pegs at x ∈ 1..=22, connects y=0 to y=23). Seat 1 = Noir = twixtbot `BLACK` (y ∈ 1..=22, connects x=0 to x=23). Colours never change with a swap: the swapped peg (x,y) becomes Black's peg (y,x) and Red plays next.
- `ludo-core` and `games/*` stay native: no `wasm-bindgen`/`js-sys`/`web-sys` in them. The rules never depend on the weights (replaying a `MatchLog` must work without them).
- Weights are not in the JS/WASM bundle: `web/public/twixt/net-f16.bin`, fetched only by a worker that needs TwixT's AI or coach.
- Engine owns all logic: every coach number, grade, key moment and take-back is computed in Rust; the web formats.
- Coach and "Annuler et réessayer" only in a local game with an AI seat; post-game review in any local game (AI or same screen); nothing online, nothing for a spectator. The coach shows nothing until clicked.
- Levels: Easy / Medium / Hard (existing `Level`). Hard thinks ~10 s per move in the browser (the user accepted more than 10 s).
- Grades from the mover's win-probability drop `loss`: Meilleur ≤ 0.01 < Bon ≤ 0.05 < Imprécision ≤ 0.10 < Erreur ≤ 0.20 < Gaffe.
- Win probability from the 3 value logits `[loss, draw, win]` of the side to move: `p = p_win + p_draw / 2` (softmax).
- Commits use the repo's local e-mail (already configured), French one-line subjects like the existing history, ending with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. `cargo fmt --all` and `cargo clippy --workspace --all-targets -- -D warnings` before each commit.
- Never panic on input: bad moves/histories return `Illegal`.

## Review Focus

1. A history containing `Swap` given to the coach or the review (position rebuild, encoding after swap, "last move" being the swap) — must work like any other move. Test in Task 6.
2. Weights missing or fetch failure in the browser — the AI must report an error, never silently play the fallback as if it were the AI. Test in Task 7 (`ensureTwixtNet` rejects with "Poids de TwixT non chargés" when the fetch fails, and the worker then rejects the `aiMove`).
3. Black to move (transposed encoding) and the position right after a swap — covered by fixtures in Task 1 and checked in Task 4.
4. Take back while the AI is thinking, and take back at the very start (nothing to undo) — Task 9 tests.
5. A blocked position where neither side can connect while holes remain — draw, not an endless game. Test in Task 3.

- Produces: the weight file format below, and the fixture JSON below (consumed by Tasks 4 and 5).

Weight file (little endian): magic `b"TWXN"`, `u32` version = 1, `u32` channels (48), `u32` blocks (20), `u32` value_hidden (80), `u32` value_reductions (4), then tensors as `f16`, in this order, every BatchNorm folded into the preceding conv/linear (`w' = w·γ/√(var+eps)`, `b' = β − mean·γ/√(var+eps)`; the stem's three convs share `primary_bn`: fold it into the sum, giving one bias):
1. `location` w [C,2,1,1], `pegs` w [C,2,5,5], `links` w [C,8,4,4], stem bias [C]
2. per block: conv1 w [C,C,5,5], b1 [C], conv2 w [C,C,5,5], b2 [C]
3. `policy_conv1` w [2,C,1,1], b [2], `policy_conv2` w [1,2,1,1] (no bias)
4. per value reduction: w [C,C,5,5], b [C]
5. `value_fc` w [H, C·2·2], b [H], `value_out` w [3,H] (no bias)

Fixture JSON: `{ "positions": [ { "moves": ["d4", …, "swap", …], "pegs": [2·24·24 numbers, the `to_input_arrays` pegs array flattened in [x][y][plane] order], "links": [8·24·24, same order, after the shift done in `to_input_arrays`], "policy": [528 logits], "value": [3 logits] } ] }`. Moves use twixtbot's notation (`Point` string, e.g. `"d4"`, and `"swap"`). Outputs are computed by PyTorch **with the weights rounded to f16 and back**, so Rust must match them to 1e-3.

pub enum Grade { Best, Good, Inaccuracy, Mistake, Blunder }       // Meilleur/Bon/Imprécision/Erreur/Gaffe

pub struct Candidate { pub at: Point, pub win: f32 }                 // win for the side to move

Key moments: the 3 largest losses ≥ 0.10 (`Mistake` or worse), in ply order.
